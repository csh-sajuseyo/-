# 뉴스 분석기 — 기사 본문 요약 (2026-11-17)

## 된 것
- 중요도 3 이상이거나 BTC·XLM 기사는 분류가 끝난 뒤 원문 페이지를 읽어 `body_summary`를 만든다(Haiku).
  - `points`: 3~5줄, 각 60자 이하. 본문을 못 읽으면 `basis: "제목만"`으로 RSS 설명에서 1~2줄.
  - `numbers`: 핵심 숫자 0~3개. 원문에 있는 숫자만 남긴다. "4,500만 달러 ↔ $45 million" 같은 단위 바꿈은 허용.
  - `basis`, `read_at`.
- 읽기 규칙:
  - robots.txt를 따른다. robots.txt를 못 읽으면(서버 오류) 그 사이트는 읽지 않는다.
  - 같은 사이트는 4초 간격, 실패하면 1번만 다시 시도.
  - 401/402/403/405/451, 로그인 페이지로 넘어감, `isAccessibleForFree=false`는 읽지 않는다.
  - 앞 3,000자만 쓴다. 메뉴·광고·관련기사·사진 설명·기자 줄·저작권 문구는 뺀다.
- 업비트 공지는 페이지가 비어 있어서, 공지 목록에 이미 쓰는 공개 API의 상세 주소로 본문을 읽는다(robots 확인 포함).
- 원문은 디스크에 저장하지 않는다. 요약만 `data/summaries.jsonl`에 덧붙인다. 원장 `news_events.jsonl`은 그대로다.
- 형식 검사를 코드로 강제한다: 15자 넘게 원문과 같은 이어진 글이 있는 줄은 버린다. 따옴표는 지운다. 60자가 넘으면 자른다.
- 비용: 장부에 `claude-haiku-5-5:summarize`로 따로 센다.
  - 요약 상한 하루 $0.10(`.env` `NEWS_FEED_SUMMARY_USD_CAP`). 호출 전 최악 비용으로 검사한다. 전체 한도 $2도 그대로 적용된다.
  - 넘으면 그날은 멈추고 `feed.json`의 `summary_status`에 「요약 멈춤(오늘 상한)」이 남는다. 00:00 KST에 풀린다.
- 지난 24시간 채우기: 수집기가 매 수집(5분)마다 24시간 안의 대상 기사를 6건씩 자동으로 채운다(시간당 최대 72건). 바로 채우려면 `run.py --summarize-backfill`.
- `feed.json`은 필드만 늘었다(`items[].body_summary`, `summary_status`, `counts.body_summaries`). 기존 필드는 그대로라 버전 2 유지. README와 `docs/FEED-FORMAT.md`에 적었다.

## 요약 예시 2개 (형식 견본)
이 작업창에는 API 키가 없어 **Haiku를 돌리지 못했다**. 아래는 실제로 읽어 온 두 기사 본문으로 이 작업창이 직접 쓴 형식 견본이다. 같은 형식 검사(줄 수·60자·15자 복사·숫자)를 통과했다. 실제 Haiku 요약은 PC에서 `REPORT_NEWS_FEED.cmd`에 2건이 나온다.

- 크로스체인 브리지 Across가 탈취됐던 웹사이트 도메인을 되찾았다고 밝힘
- 도메인 등록업체 Namecheap 쪽을 노린 사회공학 공격으로 피싱 사이트로 바뀌었음

- 피해 이용자는 전액 보상하고 며칠 안에 사고 경위를 공개할 예정
- 전체 피해 규모와 피해자 수는 아직 밝혀지지 않음
- 숫자: 없음

## 하루 예상 비용 (추정 — 실측 아님)
- 기사 1건: 입력 약 800~1,500토큰(영문 3,000자 ≈ 750토큰, 국문은 더 많음) + 출력 약 250토큰 → 약 $0.0002~0.0003.
- 대상 기사 하루 100~150건(분류된 것 중 중요도 3 이상 + 내 코인)이면 **하루 약 $0.03~0.05**. 상한 $0.10 안이다.
- 「제목만」 요약은 입력이 짧아 더 싸다.
